01 · Risks · 案前判斷

拿著簡體說明書，為什麼我們總是看不懂？

最近拿到一份 19 頁簡體美容儀器說明書 PDF，裡面寫滿專有名詞與功效描述，因而無法直接給台灣使用者用。

字都認識，文件卻不能用。

這趟接力做了什麼

把 19 頁原稿交給三棒 AI 處理，最後產出含封面、目錄與重配配圖的 28 頁 A4 繁中手冊 PDF。這頁把整套「接力賽」跑法完整拆解。

三個讓直翻失敗的風險

我們動工前先做案前判斷，找出三個讓直翻失敗的風險。這三個風險正是後面必須分棒處理的原因。

風險為什麼會失敗
其一疑似醫療描述 原稿保留大量涉及醫療行為、疾病診斷與療效宣稱的易誤認語句。若照字面翻譯會把「患者」與「禁忌症」等詞原樣留下，使得文件讀起來像醫療器材文件。
其二簡轉繁陷阱 原稿既是簡體中文，只做字形轉換遠遠不夠，專有名詞與台灣常用語都要深度在地化。否則殘留簡體用語，便會直接拉低說明書可信度。
其三格式保留 原稿帶有章節、警告、表格、配件清單與配圖，成品不能只剩純文字。版面結構必須保留，使用者才能對照實物操作。
目標定義
轉成繁中 HTML 說明書，同時移除或改寫醫療相關語句並完整保留原始格式。由於 HTML 比 PDF 好校正，定稿後再轉 PDF 也很方便。
02 · Relay · 三段接力

三段 AI 接力賽，每一棒到底在做什麼？

我們把全程排成 Plan 走向 Rewrite 走向 Dev 走向 QA，使每個階段只做一種性質的工作，讓翻譯、質檢、排版分開以使 Prompt 聚焦。出問題時，也才能歸因到正確那一棒。

交棒規則只有一條：上一階段產物永遠當草稿。每個新階段都要告訴 AI 別把草稿當正確稿，如此才能避免錯誤一路帶進決賽。

STEP 1　翻譯初版：由 DeepSeek 擔任第一棒

Rewrite 階段選用 Open Code 加 DeepSeek V4-pro 跑初版，第一個理由是省 token，使大量整理工作能用便宜模型完成。第二個理由是語境特殊，其他模型易觸發審查而拒稿，DeepSeek 則能判斷語境先給出合規版本。

我們給第一棒的指令一次講齊文件類型、合規風險與輸出要求三件事，敘述若像醫療行為便必須修正，並禁止直接簡轉繁而要求專有名詞深度轉換。不確定的名詞必須停下來發問，最後保留原格式做成 HTML 檔。

拿到 HTML 初版後先別當完稿，而把它當可編輯草稿，只確認六件事：

  • 是否真有 HTML 檔
  • 章節是否大致完整
  • 警告是否還在
  • 表格是否還在
  • 功能名稱是否太像療效宣稱
  • 簡體殘留與醫療用語掃過一遍

STEP 2　複驗校稿：由 Codex 擔任第二棒

我們在 Dev 前半段把 AI 角色從生產者切換成審稿者，拿原始 PDF 對照初版 HTML 以找出錯翻與殘留問題。能確定的直接修正，不確定的則停下來發問。

第二棒抓到好幾類殘留風險，證明初版看似完成其實並未清除風險。

類別初版殘留問題
醫療裝置語彙植入式心臟除顫器語境太接近醫療器材。
疾病描述慢性疾病與血糖血壓血脂語氣仍像禁忌症。
功能名稱走樣原 PDF 寫「五極彩光微電」，初版加料成「五極彩光微電波護理」初版自行擴寫。
功能名稱走樣原 PDF 寫「水氧噴槍」，初版寫成「水氧噴霧」與機身不符。
命名暗示原名「美斑筆」易聯想除斑，初版「煥膚筆」仍有暗示最後由使用者拍板改成最中性的「美容筆」。

我們在第二棒立下改寫原則為安全提醒保留、診斷語氣拿掉：

原文改成
患者使用者
禁忌症不建議使用情形
皮膚感染破損或紅腫滲液等描述

使文件從此讀起來像美容儀器文件。

STEP 3　排版輸出：由 Claude Code 擔任第三棒

我們在 Dev 後半段進入性質完全不同的版面工程，選用 Claude Code 整合配圖、重做排版以輸出 A4 成品 PDF。看中的是計畫模式能先確認方案再動工，且排版與理解意圖能力強，適合反覆確認的任務。

給第三棒的指令是硬規格講死、軟決策留白：要求每頁 A4、下方標頁碼、開頭加目錄頁，內文字體放大以方便閱讀，段落盡量不跨頁，有疑問就停下來問。

決策題選擇換到什麼
配圖標註HTML 重建換來繁體大字。
設計配色深藍科技感呼應儀器 UI。
內文字級16px總頁數落在 24 至 28 頁。
目錄層級章加節兼顧查找便利。
第五個決策點：計畫核准
Claude Code 把答案寫進完整計畫書並在核准後才動工，使這份計畫書完工後直接變成驗收清單——同時是起跑線也是終點線。
03 · Contrast · 為何不能一次丟

一次丟給 AI 翻譯，為什麼反而更危險？

對比舊人工直翻，才懂三段接力為何更穩。因為舊做法一人翻到底、翻譯校稿排版全混在一起，譯者沿用第一印象而使醫療語氣很難自查。

單一指令會發生什麼
「幫我翻成繁體中文」「患者」與「禁忌症」便會原樣留下。
「幫我去掉醫療內容」必要安全提醒又可能被連根拔掉。
沒指定保留格式表格與配件清單便會散成純文字而無法對照操作。
三段接力正好對症下藥：第一棒負責產出草稿、第二棒負責比對修正、第三棒負責版面與輸出，且每棒都寫下「有疑問就停下來問」這句話，使人工守門點成為四階段共用的安全網。

要停下來問人的四種典型情況

  • 功能名稱對應機身 UI 按鈕，便不能擅改。
  • 原文有功效暗示，改名又怕影響辨識，必須權衡。
  • 疑似品牌專有名詞，不確定能否改。
  • 安全提醒能刪還是只能改寫。

初版完整不代表風險清除，這正是最大迷思。因為第二棒對照原稿仍抓出「實銷性」與「其它」等錯字，修正清單與待確認項目逐項列出，確認 HTML 可用才交棒。

04 · QA · 完工複驗

排版輸出這最後一棒，我們該怎麼驗收？

我們在 QA 階段堅持完工不等於交付，用一段複驗指令同時對照計畫與「清晰易讀」的目標，使兩個基準並行，以避免規格全對卻不好讀。

檢查項目方法結果
頁面尺寸程式檢查 28 頁全為 210 × 297 mm
內文字級程式統計字級分布12pt ＝ 16px
簡體殘留全文比對簡體字表無殘留
頁尾頁碼逐頁檢查全數吻合
目錄頁碼抽 12 個目錄條目核對全數吻合
圖編號遞增連續驗證無重複
版面全 28 頁逐頁目檢無段落切斷，標註對位正確

QA 很適合換成 AI 執行

因為基準是計畫書而計畫書是 AI 讀得懂的文件，可要求逐項比對成品與計畫並列出偏差與原因。再執行程式化斷言以驗證尺寸頁碼目錄，並把每頁渲染成圖以親自檢視版面。

Plan 寫得越清楚、QA 越好自動化，因為計畫書本身就是驗收清單而 AI 只需逐項執行。

程式化斷言交給程式，好不好讀留給眼睛。

跨階段通用五條準則

  1. 每階段只做一種性質的工作。
  2. 上一產物永遠當草稿。
  3. 「有疑問就停下來問」這句話每階段都要寫。
  4. 先計畫再動工。
  5. 完工不等於交付，QA 才是終點。

有合規與格式風險的文件都適用這套跑法。
