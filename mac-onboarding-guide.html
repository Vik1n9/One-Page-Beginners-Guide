01 · Setup · 為什麼是這八步

全新的 Mac，為什麼不是開機就能用？

剛拆封的 Mac 出廠只帶瀏覽器與內建 app，AI 工具需要的安裝器、終端機、容器與程式執行環境一個都沒有。這八個步驟就是把缺口一次補齊，順序是照相依關係排的，不是照重要性排的。

裝什麼不難，難的是順序。

多數新手卡住的原因不是某個指令打錯，而是拿第三步的工具去做第六步的事。下面這張表先把全貌攤開，建議先看過一遍再動手。

步驟裝什麼為什麼排在這裡
STEP 1Apple 帳號登入先確定這台機器屬於你，後面的下載與授權才有對象。
STEP 2macOS 系統更新一次把版本拉到最新，後面六步的版本條件全部滿足。
STEP 3Homebrew後面五步全部靠它安裝，沒有它就得一個個手動下載。
STEP 4ChatGPT 桌面 app這是你操作 Codex 的地方，裝好就能開始用。
STEP 5Ghostty後面的指令都在這裡打，越早換越不用學兩套習慣。
STEP 6Docker Desktop提供用完即丟的乾淨環境，讓專案不會弄髒你的 Mac。
STEP 7Git、Node.js、PythonAI 寫出來的程式要靠這三個才能真的跑起來。
STEP 8GitHub 協作設定讓每次修改都能回退，也才能和別人共用同一份程式碼。
本頁只寫 Apple 晶片（M 系列）的 Mac。確認方式：點左上角 Apple 選單 →「關於這台 Mac」，晶片欄位看到 M 開頭的名稱就是。Intel Mac 的安裝路徑與本頁不同，請勿照做。
照順序做，不要跳號
每一步都假設前一步已經完成。跳過任何一步，後面的指令不會提示你漏了什麼，只會丟出一句看不懂的錯誤訊息。
02 · Step 1 · Apple 帳號

STEP 1　如何用 iPhone 把 Apple 帳號帶進新 Mac？

Apple 帳號是這台 Mac 之後下載 app、同步 iCloud 與使用「尋找」時的同一個身分，登錯就等於把你的資料分進兩個帳號。用 iPhone 上已經登入的那一組，可以省去重打密碼與等驗證碼，也避免在設定精靈裡手滑新建了第二個帳號。

這一章全部是點擊操作，沒有任何指令。新機第一次開機會自動進入「設定輔助程式」，照著走完即可。

開機後的順序

  1. 按下電源鍵（或直接掀開螢幕），選語言「繁體中文」、地區「台灣」。
  2. 連上 Wi-Fi。
  3. 畫面出現「快速開始」時，把 iPhone 靠近 Mac。
  4. iPhone 跳出「設定新的 Mac」，點「繼續」。
  5. 用 iPhone 相機對準 Mac 畫面上的動畫圖樣。
  6. 在 Mac 上輸入你的 iPhone 解鎖密碼，Apple 帳號與 Wi-Fi 設定會一起帶過來。
  7. 建立這台 Mac 的本機使用者帳號與密碼。
  8. 依畫面指示設定 Touch ID，並開啟 FileVault 磁碟加密。

如果沒有出現「快速開始」

兩條路什麼時候用會被問到什麼
快速開始（靠近 iPhone）手邊有已登入同一個 Apple 帳號的 iPhone，且兩台都開著藍牙與 Wi-FiiPhone 解鎖密碼
手動輸入沒有 iPhone 在手邊，或畫面沒跳出快速開始Apple 帳號、密碼，以及送到其他 Apple 裝置上的兩步驟驗證碼

兩條路的結果完全相同，差別只在要打多少字。手動輸入時若收不到驗證碼，可在 iPhone 的「設定 → 你的名字 → 登入與安全性」確認信任裝置清單。

這一步涉及你的帳號安全，請先讀完再操作。本機使用者帳號密碼與 Apple 帳號密碼是兩組不同的密碼，兩個都要自己記住。不要用別人的 Apple 帳號登入你的 Mac。兩步驟驗證碼不得轉述給任何人，包含自稱客服的來電。若這台 Mac 是二手或他人轉讓，務必先確認原持有者已經移除「啟用鎖定」，否則後面全部白做。
確認你真的登入了
點 Apple 選單 →「系統設定」，左上角出現你的名字與 Apple 帳號，就代表這一步完成了。
03 · Step 2 · 系統更新

STEP 2　為什麼第一件事是把 macOS 更新到最新版？

後面要裝的每個 app 都有最低 macOS 版本要求，版本不夠時 Homebrew 會直接拒絕安裝，而錯誤訊息不會告訴新手「去更新系統」。新機出廠通常停在出貨當時的版本，在這裡更新一次，後面六步的版本條件就全部滿足，不必再逐步檢查。

更新步驟

  1. Apple 選單 →「系統設定」。
  2. 左側選「一般」→ 右側選「軟體更新」。
  3. 等它檢查完畢（可能要一兩分鐘）。
  4. 出現「立即升級」或「立即更新」就按下去。

更新期間 Mac 會自動重新開機數次，屬於正常現象，不要中途強制關機。整個過程通常需要 30 到 60 分鐘，視網路速度而定。

開始前請插上電源，並確認重要檔案已經在 iCloud 或外接硬碟裡留有一份。更新進行中不要闔上螢幕，也不要讓 Mac 進入睡眠。
更新一次，後面都不用再管版本
這一步做完，本頁後面所有要安裝的東西都不會再因為系統版本被擋下來。之後不會再看到任何「需要 macOS 幾以上」的提醒。
04 · Step 3 · Homebrew

STEP 3　Homebrew 要怎麼裝，才不會裝完找不到？

macOS 的 App Store 拿不到開發工具，Homebrew 是用一行指令安裝、更新與移除這些工具的統一入口，後面五個步驟全部靠它。手動下載 dmg 一個個拖進「應用程式」不會留下任何紀錄，換機或重灌時你得靠記憶重來一次。

可以把它想成終端機世界的 App Store：你打一行字，它負責下載、解壓、放到正確位置，之後還能一次更新全部。

先打開終端機

按 Command + 空白鍵 叫出搜尋列，輸入 terminal，按 Enter。這是 macOS 內建的終端機，先用它就好，Ghostty 要到 STEP 5 才裝。

安裝 Homebrew

這一行會從 Homebrew 官方網址下載安裝腳本並執行，所以只從官方網站 brew.sh 複製，不要從論壇貼文複製。過程中會要求輸入你的本機登入密碼；打字時畫面上不會顯示任何字元，這是正常的，打完直接按 Enter。它也可能順帶安裝 Xcode Command Line Tools，按 Enter 讓它跑完即可。

安裝完最關鍵的三行

這是整頁最容易失敗的一步。Apple 晶片的 Homebrew 裝在 /opt/homebrew，而這個位置不在系統預設的搜尋路徑裡。安裝程式跑完後印出的 Next steps 就是上面這三行，多數新手直接關掉視窗，下次再打 brew 就得到 zsh: command not found: brew，然後以為安裝失敗、整個重來。

驗證

第一行會印出版本號，第二行應該印出 /opt/homebrew/bin/brew。兩行都有正確輸出才算完成。

一個入口，之後都用它
日後想把所有工具更新到最新版，只要一行 brew update && brew upgrade。
05 · Step 4 · ChatGPT App

STEP 4　安裝 ChatGPT 桌面 app，把 Codex 帶上桌面

Codex 是能直接讀寫你電腦上專案檔案的編碼代理，桌面 app 比瀏覽器版多了與本機檔案系統連線這一層能力。用 Homebrew 安裝可以讓它跟其他工具一起被 brew upgrade 管理，不必自己記得去官網抓新版。

第一次開啟

  1. 按 Command + 空白鍵，輸入 ChatGPT，按 Enter。
  2. 若跳出未驗證開發者的提示，到「系統設定 →『隱私權與安全性』」，往下捲找到該提示，按「仍要打開」。
  3. 用你的 OpenAI 帳號登入。
  4. 在 app 內切換到 Codex 模式。
授權範圍請從小開始。Codex 會直接修改你授權的資料夾內的檔案。第一次請先指向一個空的測試資料夾，實際看過它改了哪些東西，再放行真正的專案。不要在第一次就授權整個「文件」或「桌面」。
確認你在 Codex 模式
app 裡有多個模式，切錯了它就只會跟你聊天，不會碰你的檔案。
06 · Step 5 · Ghostty

STEP 5　為什麼要把終端機換成 Ghostty？

內建的「終端機」能用，但跟 AI agent 長時間對話時，畫面刷新速度、中文字寬與分頁管理都會拖慢你判斷輸出的速度。換終端機是一次性成本，越早換越不用把操作習慣學兩遍。

裝好後按 Command + 空白鍵，輸入 Ghostty 打開它。開著的時候在 Dock 上按右鍵 →「選項」→「保留在 Dock 中」，之後就不用再搜尋。

順便做一個免費的驗收。在 Ghostty 裡再打一次 brew --version。有輸出，代表 STEP 3 的三行確實寫進了 ~/.zprofile，而不是只在當時那個視窗生效。沒有輸出，就回 STEP 3 重跑那三行。
之後的指令都打在這裡
本頁後面所有指令都在 Ghostty 裡執行，內建的終端機可以關掉了。
07 · Step 6 · Docker

STEP 6　Docker Desktop 裝好之後，該看到什麼？

許多專案與 AI agent 的說明都假設你能「在容器裡跑」，而容器等於一台用完即丟的乾淨電腦，讓專案的相依套件不會弄髒你的 Mac。Docker Desktop 同時提供背景引擎與圖形介面，沒有它，docker 指令沒有任何東西可以連。

注意套件名稱是 docker-desktop，沒有名叫 docker 的 cask，打錯只會得到找不到的錯誤。

第一次啟動

  1. 到「應用程式」點開 Docker Desktop。
  2. 同意授權條款。
  3. 輸入本機密碼，讓它安裝背景元件。
  4. 等螢幕右上角的選單列出現鯨魚圖示，那才代表引擎真的在跑。

第二行會下載一個極小的測試映像檔並執行，看到一段以 Hello from Docker! 開頭的訊息就成功了。

Docker Desktop 的授權條款依使用情境而異，公司配發的電腦請先向 IT 確認再安裝。不使用時，從選單列的鯨魚圖示選 Quit，它在背景會持續佔用記憶體。
看到鯨魚才算成功
選單列沒有鯨魚圖示，docker 指令就連不上任何東西，再怎麼重打也沒用。
08 · Step 7 · 執行環境

STEP 7　Git、Node.js 與 Python 為什麼要一起裝？

AI agent 幾乎都假設你的電腦上有 Git 可以記錄每次修改、有 Node.js 或 Python 可以實際執行它寫出來的程式。缺任何一個，對話會在中途停在 command not found，而新手無從判斷是 AI 寫錯了還是環境沒裝。

工具Homebrew 名稱版本做什麼
Gitgit2.55.0記錄每一次修改，隨時可以退回上一版。
Node.jsnode26.9.0執行 JavaScript／TypeScript 專案，附帶套件管理工具 npm。
Pythonpython3.14.7執行 Python 腳本，指令名稱是 python3。
兩個容易混淆的地方。第一，macOS 內建的 git 是 Xcode Command Line Tools 附帶的版本，通常比較舊；用 Homebrew 裝過之後，which git 會指向 /opt/homebrew/bin/git。第二，Python 的指令是 python3，不是 python。

四行都印出版本號就代表完成。版本數字與上表不完全一致是正常的，它們會持續更新。

09 · Step 8 · GitHub 協作

STEP 8　Git 與 GitHub 要怎麼設定才能協作？

AI agent 一次會改動好幾個檔案，Git 讓每一次修改都留下紀錄、隨時能退回上一版，這是放手讓 AI 動你的專案的前提。GitHub 則讓同一份程式碼能在你、隊友與其他機器之間同步，也是 AI agent 讀取專案脈絡與提交 Pull Request 的地方。

六個名詞先講清楚

這六個字之後會不斷出現。先花兩分鐘看過，後面的指令才不會變成在背咒語。

名詞白話解釋
repository（倉庫）一個專案資料夾，加上它從第一天到現在的完整修改歷史。
commit（提交）一個存檔點，記下「這一刻所有檔案長什麼樣」。
branch（分支）一條平行的修改線，改壞了不會影響主線。
remote（遠端）GitHub 上的那一份，用 push 與 pull 跟本機同步。
clone（複製）把遠端那一份完整抓到自己電腦。
Pull Request請別人看過你這批修改，再決定要不要併進主線。

設定你的 Git 身分

第三行把新專案的預設分支名設成 main，與 GitHub 現在的預設一致，可以少一次改名。

這裡填的資料會被公開。名字與信箱會寫進每一次提交紀錄，推上 GitHub 等公開平台之後無法私下撤回。不想公開真實信箱的人，請先到 GitHub 的帳號設定申請 @users.noreply.github.com 代理信箱，再填進上面第二行。

安裝 GitHub CLI 並登入

gh auth login 是互動式的，用方向鍵與 Enter 依序選：GitHub.com → SSH → 讓它產生新的 SSH 金鑰 → Login with a web browser → 複製畫面上的一次性代碼 → 到瀏覽器貼上並授權。

為什麼不自己產生金鑰？多數教學會叫你先用 ssh-keygen 產生金鑰、複製公鑰、再貼到 GitHub 網頁的設定裡，那是三個各自都會出錯的步驟。gh auth login 把這三件事包進同一個問答流程，對新手失誤率低得多。手動流程仍然有效，只是不必在第一天學。

日常使用：一個完整循環

動作指令在做什麼
取回專案git clone <網址>把 GitHub 上的專案抓到本機。
開分支git switch -c 分支名在不動主線的前提下改東西。
看改了什麼git status、git diff確認 AI 動過哪些檔案。
記錄一次修改git add -A 後 git commit -m "訊息"存成一個可回退的檢查點。
推上雲端git push -u origin 分支名讓隊友看得到你的修改。
開 Pull Requestgh pr create --draft請人審這一批修改。

改壞了怎麼退回

這一節是整章對 AI 使用者最有價值的部分。知道怎麼退回，你才敢放手讓它改。

狀況指令說明
還沒 commit，想全部丟掉git restore .所有檔案回到上一個存檔點。
想看做過哪些存檔點git log --oneline一行一個，前面那串是它的代碼。
想知道某次改了什麼git show <代碼>代碼取自上一行。
分支開錯了git switch 分支名切回去，已經 commit 的東西不會消失。
先 commit，再讓 AI 動手
養成動工前先 commit 一次的習慣。AI 改壞了只要 git restore . 就能回到原狀，不必從頭來過。
10 · Computer Use · 讓它直接動手

Computer Use 能讓 ChatGPT 直接操作你的 Mac 嗎？

可以。Computer Use 讓 ChatGPT 直接看著畫面操作 Mac 上的 app，適合那些沒有指令可用、只能靠點擊完成的事。它不是前面八步的替代品——它刻意不能操作終端機，兩者補的是不同的洞。

能用指令做的，留給終端機；只能用滑鼠做的，才交給它。

怎麼打開

Computer Use 在 ChatGPT 的 Work 與 Codex 方案中提供，且限支援的地區。

  1. 開啟 ChatGPT 桌面 app，切換到 Work 或 Codex。
  2. 進入 Plugins → Computer Use。
  3. 如果出現提示，先按 Install plugin，再按 Enable。
  4. 把 MCP server 與 skill 的開關打開。
  5. 按 Try now。

兩個系統權限

第一次執行時 macOS 會跳出請求，也可以自己去開。路徑是「系統設定 →『隱私權與安全性』」，在螢幕錄製與輔助使用兩個項目底下，找到 Codex Computer Use 勾選。

權限作用
螢幕錄製讓 ChatGPT 看得見目標 app 的畫面。
輔助使用讓 ChatGPT 能點擊、輸入與操作介面。

每個 app 都要你點頭

任務開始前，ChatGPT 會針對它要用的每個 app 個別徵求同意。可以選「Always allow」讓該 app 之後不再詢問；想收回時，到 app 設定裡的 Computer Use 區塊把它從清單移除。

能做什麼、不能做什麼

適合交給它它做不到
測試 macOS app 或 iOS 模擬器的操作流程自動化終端機 app
自動化瀏覽器上的任務自動化 ChatGPT 自己
重現只在圖形介面才看得到的 bug以管理員身分驗證
修改那些只能在 UI 裡點的設定替你核准系統權限提示
取得外掛拿不到的資料—
跨多個 app 的連續流程—

在 macOS 上它可以在背景執行，你同時做別的事。

安全上的幾件事。任務範圍盡量窄，一次針對一個 app 或一條流程。牽涉帳號、付款、憑證或安全設定時，人要在場。用不到的敏感 app 先關掉；如果它會用到已登入帳號的瀏覽器，換一個瀏覽器或先把原本那個關掉。每個權限提示都看過再按，「Always allow」只給你信任的 app。一旦發現它在操作錯的視窗，立刻取消任務。
它看得到什麼。Computer Use 拍下的截圖適用你既有的 ChatGPT 資料控制設定。任務進行期間，畫面內容、瀏覽器頁面與開啟的檔案都會成為 ChatGPT 的脈絡。檔案修改與 shell 指令仍然走 ChatGPT 原本的核准與沙箱設定。
