01 · Habit · 壞習慣

為什麼不能一直在同一個對話裡做下去？

多數人用 AI 的方式是把所有東西丟進同一個對話視窗：規矩、做法、連線設定、專案脈絡全部混在一起。對話關了就全部消失，換一個工具就從頭來過。這不是工具的問題，是狀態放錯了地方。

程式開發有一個早已驗證的做法：專案的狀態活在資料夾與 git 裡，工具只是來讀取它。換編輯器、換 AI、換機器，資料夾不動，專案就在。把同一個做法搬到 AI 工作流，需要搬的東西只有五項：

  1. AGENTS.md — 你對 AI 的規矩。
  2. Skills — 你的做法，寫成可觸發的技能檔。
  3. MCP / Plugins — 外部連線，寫成設定檔。
  4. repomix — 把整個專案打包成 AI 吃得下的格式。
  5. opencode 驗證 — 換一個 AI 開啟同一個資料夾，逐項確認上面的東西都還在。

工具會換，資料夾不會。

指南 12 已經裝好 Git 與 GitHub。那一篇把 git 當成「改壞了的救兵」；這一篇把 git 升級成「專案記憶的載體」。六步做完，你的 AI 專案不再活在某一輪對話裡，而是活在資料夾裡，誰 clone 下來都能接手。

02 · Step 1 · 規矩

STEP 1　把「我的規矩」從對話搬進 AGENTS.md

你在每一輪對話開頭重複貼上的那段話，就是該寫成檔案的東西。把它存成 repo 根目錄的 AGENTS.md，之後每一個 AI 開啟這個資料夾，第一件事就是讀它。

AGENTS.md 是跨工具通用的檔案名稱，Codex、Claude Code、Cursor 都會自動讀取。不要用其他自訂名稱，那只有特定工具認得。

03 · Step 2 · 做法

STEP 2　把「我的做法」寫成一個會動的技能

AGENTS.md 解決「規矩」，Skill 解決「做法」。規矩是每次都要遵守的，做法是特定任務才觸發的。一個 Skill 就是一個資料夾，裡面放一份 SKILL.md，描述做什麼、什麼時候觸發、怎麼做。

先看一個最小的 Skill

把這個資料夾放進 repo 的 .claude/skills/ 或 .agents/skills/，git add 之後，任何一個 AI 打開這個 repo 都能呼叫它。

三個階段：Discovery → Activation → Execution

Discovery：AI 啟動時只讀 Skill 的 name 與 description，不讀內容。以這個 repo 裡實際安裝的 kami 技能為例，它佔了 110 個檔案、約 1.7 MB，但啟動時進入 context 的只有 name 加 description 那幾行字。這意味著裝一百個技能也不會拖慢啟動。

Activation：AI 判斷你的請求符合 description 裡的觸發條件，載入完整 SKILL.md。

Execution：AI 照著 SKILL.md 的步驟執行。

description 怎麼寫

回來看 kami 的 description，它塞了多種語言的觸發詞：

中文、簡體、日文、英文全部列進去。因為你不知道下一輪對話會用哪一種語言下指令。同一份 SKILL.md 在 Codex、Claude Code、Cursor 都能用，因為它們都支援 Agent Skills 格式（agentskills.io）。

description 寫得不好，技能就永遠不會被觸發。這是新手最常踩的坑：Skill 寫完了，AI 從不呼叫它。原因幾乎都是 description 裡缺少你實際會用的觸發詞。把你自己會怎麼問寫進去，而不是描述它「能做什麼」。

成功訊號

git add 進 repo，在另一台機器 git clone 下來，用同一句觸發詞呼叫它，能正常觸發就算完成。

04 · Step 3 · 別人的做法

STEP 3　到哪裡找現成技能？裝在哪一層？

不必每個技能都自己寫。skills.sh 目錄與 npx skills 指令讓你搜尋、安裝、管理別人寫好的技能。關鍵問題是：這個技能該跟著 repo 走，還是只留在你自己身上。

npx skills 能做的事

指令做什麼
npx skills find <關鍵字>在 skills.sh 搜尋符合的技能。
npx skills add <來源>安裝指定技能到專案或全域。
npx skills list列出目前已安裝的技能與實際路徑。
npx skills update更新已安裝的技能。
npx skills remove <名稱>移除指定技能。
npx skills init <名稱>建立一個新的技能骨架。

裝在哪一層

判斷標準只有一個：這個技能該不該跟著 repo 走？

  • Yes → 專案層級：預設安裝位置在 repo 內，git add 之後任何人都 clone 得到。適合這個專案專屬的做法。
  • No → 全域：加 -g 安裝到 ~/.agents/skills/，只有你自己用得到。適合你個人的習慣，跟專案無關。

symlink 還是 copy

npx skills add 預設用 symlink 連結到全域技能目錄，意思是全域更新一次，專案裡跟著更新。如果你想把技能凍結在當下版本，加 --copy 把檔案直接複製進 repo。

不要背路徑。各工具的安裝位置不同，用 npx skills list 看實際落在哪裡。如果安裝到專案層級的 symlink 被 git add 進了 repo，記得在 .gitignore 排除——細節見指南 14 第六章的 .gitignore 規則。

05 · Step 4 · 連線

STEP 4　MCP 與 Plugins：把外部連線寫成設定，不是點一點

Skills 管「怎麼做」，MCP 管「能存取與控制什麼」，Plugins 是把前面兩項打包分發的形式。把連線寫成設定檔，才能跟著 repo 走，不必每次換工具重新點一遍。

路徑：Settings → MCP servers → Add server → 填入設定 → 重啟 app。Plugins 的路徑：Plugins 分頁 → + 安裝。Plugins 安裝後必須開一輪新對話才會生效。

IDE 擴充功能不支援 Plugins。Cursor、VS Code 等 IDE 內的 AI 擴充功能有自己的外掛格式，與 ChatGPT 桌面 app 的 Plugins 不相容。Skills 與 MCP 設定仍然通用，只有 Plugins 這一層受限於桌面 app。
「Sign in with ChatGPT」不等於授權資料存取。這個按鈕只讓你用 ChatGPT 帳號的身分登入第三方服務，分享的只有名稱、信箱與頭像，不包含你的對話紀錄或檔案存取權限。資料授權是另外一組設定，請各自確認。

Secrets

API token 等敏感資訊用環境變數傳入，不要寫死在設定檔裡。慣例是把 token 放在 .env 檔，而 .env 永遠不 commit（見指南 14 第六章 .gitignore 規則）。

06 · Step 5 · 交接

STEP 5　怎麼讓任何一個 AI 快速吃下整個專案？

前面四步把狀態搬進了資料夾，但 AI 的 context window 有限，不可能一次讀完整個 repo。repomix 把整個專案打包成 AI 吃得下的單一檔案，用 Tree-sitter 抽取結構，壓縮率約 70%。輸出檔放進 .gitignore，不進 repo。

repomix

執行後會產出一個 repomix-output.xml（或 .txt），把 repo 裡的檔案結構與內容壓縮成一份。拿去貼給任何一個 AI，它就能讀到整個專案。

配套工具

工具安裝做什麼
repomixnpm install -g repomix把 repo 打包成 AI 友善格式，Tree-sitter 抽取，約 70% 壓縮。
rtkbrew install rtkCLI 輸出壓縮代理，平均約 56%、最高 90% 壓縮率，Apache-2.0 授權。
ccusage—讀取 AI 工具的 session log，計算本次對話的成本。
這一步是選擇性的。repomix 與 rtk 都不在主線流程裡，不安裝不會影響前面五步的結果。它們解決的是「專案太大、AI 吃不下」的問題，等你遇到時再裝就好。

成功訊號

對同一個 repo 跑兩次 repomix，比較前後輸出。第二次刻意排除一些不重要的目錄（用 --ignore），輸出明顯變短，但你需要的資訊仍在裡面，就代表壓縮有效。

07 · Step 6 · 驗證

STEP 6　opencode：換一個 AI，專案還在嗎？

前面五步把東西都搬進資料夾了。這一步是驗收：換一個完全不同的 AI agent，打開同一個資料夾，逐項確認前面的努力真的可攜。

驗證清單

  1. AGENTS.md 會被讀到：開啟新對話，不貼任何東西，看 AI 是否自動遵循你的規矩。
  2. Chapter 03 的 Skill 可以被呼叫：用觸發詞呼叫它，確認能正常執行。
  3. MCP 連線可用：呼叫 MCP server 提供的工具，確認有回應。

如果三項都通過，代表你的專案已經脫離對單一 AI 的依賴。

為什麼用 opencode 驗證

opencode 是開源的、可換 provider 的 AI 終端工具，原生支援 Agent Skills 與 MCP。用它來驗證，等於用一個跟你原來完全不同的 AI 來開同一個資料夾，最能檢驗可攜性。

安裝 opencode 桌面版

第一次啟動會讓你選擇登入方式。設定檔放在 ~/.config/opencode/opencode.json。

桌面版相比 CLI 版多了幾項好處：可以同時開多個 session 平行工作、內建編輯器直接看 diff、支援拖放檔案進對話。

桌面版目前仍是 beta。介面與功能可能變動，遇到問題時可用 CLI 版 npx opencode 備援。

成功訊號

你沒有重新貼上任何東西，opencode 已經知道這個專案怎麼做。它讀得到 AGENTS.md、呼叫得到你裝的 Skill、連得上你設定的 MCP。這一步通過，前面五步才算真正完成。

08 · Payoff · 誰都能接手

做完這六步，你換回了什麼？

一次 git clone 還原整個工作環境。換機器、換人、換 AI，全部接得上。這就是程式開發早就驗證過的可攜性，現在你的 AI 專案也有了。

安全與版本

Skills 是程式碼，應該被當作軟體對待。以這個 repo 裡實際安裝的 kami 為例：它的 scripts/check-update.sh 在每天第一次執行時連線 GitHub 檢查更新，而且 SKILL.md 裡主動寫明「不上傳使用者的檔案內容」 — 這就是可審查的樣子。

腳本內容有沒有連到外部伺服器、上傳檔案的邏輯。
