01 · Why · 換掉供應商

為什麼要在自己的電腦上跑模型？什麼時候不該？

前面十三篇把規則、方法、環境都放進了資料夾。下一個自然的問題是：那個幫你思考的模型，能不能也換成本機的？答案是能，但要先搞清楚代價。

跑本地模型有三個真實的好處，也有三個真實的代價。

好處代價
一斷網也能用。飛機上、捷運上、基地台掛了，照樣能問問題。速度慢。同樣一句回答，本地比雲端慢五到二十倍。
二資料不出這台電腦。專案內碼、客戶資料、私人筆記，都不會經過任何伺服器。能力較弱。本地跑得動的模型，推理與寫 code 的能力比不上同代的雲端模型。
三沒有計費。跑多少都不用付錢，不用担心 token 用完。吃記憶體。模型越大越需要統一記憶體，8GB 的 Mac 幾乎什麼都跑不了。

本地模型是備份與隱私選項，不是雲端的替代品。

維度雲端模型本地模型
速度秒回慢，等得起才用
品質同代最強落後一到兩代
隱私資料經過伺服器資料不出本機
費用依用量計費免費，但吃硬體
可用性需要網路斷網也能用
先搞清楚用途
本地模型解決的是「斷網」與「資料不外流」兩個問題，不解決「模型不夠聰明」的問題。如果你的主要需求是寫 code 的品質，留在雲端。
02 · Limit · 記憶體對照表

我的 Mac 跑得動多大的模型？

第一件事不是裝軟體，而是打開「關於這台 Mac」看你的統一記憶體是多少。模型能不能跑，取決於記憶體，不是硬碟空間。

硬碟是停車場：模型檔放得下，不代表跑得動。記憶體（統一記憶體中能分配給 GPU 的那一部分）才是車道：整個模型的權重必須全部載進記憶體才能執行，不夠大就開不了，或慢到無法使用。選模型看下面這張表，不要看硬碟剩餘空間。

量化（Q4）是把每個模型權重值從 16 位元浮點數壓縮到 4 位元整數，讓同一個模型佔用更少的記憶體，代價是品質稍微下降。這是本地跑模型的基本前提，下面的對照表全部以 Q4 為基準。

統一記憶體可跑參數（Q4）體驗能寫 code 嗎？
8 GB~3B基本對話，偶爾詞不達意不行。太小，無法理解程式結構
16 GB~7-8B可用，回覆偶有卡頓基本補全可以。簡單的函式重寫與變數命名
24 GB~14B順暢，回應品質明顯提升簡單重寫可以。短函式與樣板程式碼
32 GB~30B（Qwen3-Coder 30B，MoE：30B 總參數但每次只啟動 3.3B）舒適，接近日常可用中小任務可以。多檔案重構、專案問答
64 GB~70B接近雲端 4o 水準可以。長鏈推理、大型重構都撐得住
macOS 會限制 GPU 能使用的統一記憶體比例。統一記憶體 ≤ 36GB 的機種，GPU 最多只能用約 66%；超過 36GB 的機種，比例提高到約 75%。這是新手最常誤判的地方：以為 32GB 的 Mac 能跑 32GB 的模型，實際上 GPU 只能分到約 21GB。上面那張表已經把這個限制算進去了。
記憶體決定上限
打開「關於這台 Mac」，記下你的統一記憶體數字，對照上面的表。這就是你在後續步驟能選的模型上限。
03 · Step 1 · 先聽到聲音

STEP 1　LM Studio：最快讓本機說出第一句話

先裝圖形介面，因為你能直接看到記憶體使用量、能比較 GGUF 與 MLX 兩種格式、不用背任何指令。等確認模型在你的 Mac 上跑得動，再用下一章的 Ollama 把同樣的模型交給程式使用。

選三種情境，每種只推薦一個模型。

情境推薦模型模型大小最低記憶體
只想先聽到第一句話Qwen2.5-3B-Instruct~2 GB8 GB
想有一個能對話的助手Llama 3.1 8B Instruct~5 GB16 GB
想要能幫忙寫 codeQwen3-Coder 30B~19 GB32 GB

下載模型時注意看日期，LM Studio 搜尋結果裡會顯示上傳時間，優先選三個月內更新的版本。過舊的模型檔可能不相容目前的 LM Studio 版本。

MLX 與 GGUF 的差別

LM Studio 提供兩種格式：GGUF 是跨平台通用格式，MLX 是 Apple 晶片專用引擎，在 Mac 上比 GGUF 更快。如果你的 Mac 是 Apple 晶片（M 系列），優先選 MLX 格式。

MLX 格式有版本要求。MLX 只支援 macOS 14 以上、Apple 晶片（M 系列）。Intel Mac 不支援 MLX，只能用 GGUF。確認方式：Apple 選單 →「關於這台 Mac」，看 macOS 版本與晶片欄位。

驗證

  1. 打開 LM Studio，在搜尋欄輸入上面推薦的模型名稱。
  2. 選一個 Q4 量化的版本，點下載。
  3. 下載完成後，切到左側的聊天頁面，選剛下載的模型。
  4. 打一句話，等它回應。
  5. 關掉 Wi-Fi，再打一句話。它還能回應，就代表成功了。
關 Wi-Fi 還能回答
斷網後仍然能回應，代表模型真的在你的 Mac 上執行，不是偷偷連到遠端伺服器。
04 · Step 2 · 給程式用的

STEP 2　已經有 LM Studio 了，為什麼還要裝 Ollama？

LM Studio 是給人類用的：打開圖形介面、選模型、聊天。Ollama 是給程式用的：它在背景提供一個常駐的 API，任何能發 HTTP 請求的程式都能呼叫它。opencode 就是透過這個 API 跟本地模型對話。

四個指令就夠

指令做什麼
ollama pull qwen3-coder:30b從官方倉庫下載模型到本機。
ollama run qwen3-coder:30b在終端機裡直接跟這個模型對話。
ollama list列出本機已經下載的所有模型。
ollama ps看目前正在記憶體裡載入的模型。

驗證 API 是否在線

有輸出 JSON 就代表 Ollama 的背景 API 正在運作。如果看到 connection refused，代表 Ollama 沒有啟動，到「應用程式」資料夾點開它即可。

不想裝兩個？LM Studio 也提供 OpenAI 相容的 API，預設在 http://127.0.0.1:1234/v1。下一章的設定步驟兩條路都能走，到時候再選就好。
程式能連才算數
curl 有輸出 JSON，就代表你的 Mac 現在有一台本地的模型伺服器，任何程式都能連。
05 · Step 3 · 只換引擎

STEP 3　同一個專案資料夾，只把引擎換成本機

前面兩步把模型準備好了。這一步只做一件事：把 opencode 的模型引擎從雲端換成本機。專案資料夾、AGENTS.md、規則檔全部不動，只換背後思考的那顆引擎。

兩條路，選一條走。

路線一 CLI 一鍵啟動

Ollama 提供 ollama launch 指令，可以直接啟動 opencode 並指向本機模型。它採用內联設定，不會覆蓋你現有的設定檔。

如果只想產生設定檔而不啟動，加 --config 參數。

路線二手動設定檔

如果你用的是 opencode 桌面版，或是想更清楚控制設定，可以手動編輯 opencode.json。下面是 v2 格式的設定，放在專案根目錄。

拔掉網路線，打開同一個專案資料夾，AGENTS.md 跟前面章節設定的 skill 仍然正常運作。這代表引擎已經成功從雲端換成本機，而專案的所有規則都沒有被動到。

拔網後照樣生效
同一個專案、同一套規則，只是背後思考的模型換了。隨時可以切回雲端，設定檔裡改一個 endpoint 就好。
06 · Payoff · 留著還是關掉

跑起來之後，Mac 會發生什麼事？

本地模型在跑的時候，你的 Mac 會變熱、風扇會轉、耗電量會增加、記憶體壓力會上升。這些都是正常的，但你需要知道怎麼判斷「什麼時候該關掉它」。

該看到什麼

打開「活動監視器」→「記憶體」分頁，看下方的記憶體壓力圖表。綠色代表充裕，黃色代表開始吃緊，紅色代表記憶體不足、系統正在用硬碟交換。本地模型跑起來時，記憶體壓力上升是預期的，但如果持續停在紅色，就該關掉模型或換小一級的。

狀況該怎麼辦
風扇持續高速運轉模型太大，換小一級。或讓 Mac 散熱（不要放在棉被上）
記憶體壓力長期在紅色關掉其他吃記憶體的 app，或關掉模型
電池消耗異常快插上電源。本地推理很耗電，不建議用電池跑
不需要用了關掉 Ollama 或 LM Studio，釋放記憶體給其他 app

什麼時候該回到雲端

當你發現本地模型的回覆品質明顯不夠用、需要長鏈推理、或是趕時間不想等，就把 opencode 的設定檔裡 endpoint 改回雲端。設定檔裡換一行就好，不需要重新安裝任何東西。

本地模型不是隱私的萬靈丹。模型本身確實不會把資料傳出去，但你在指南 13 安裝的 plugin 與 MCP server 仍然會連線到網路。隱私的邊界不只在模型，也在所有你授權出去的工具。

本地跑模型會產生大檔與設定檔，其中有些絕對不能提交到 Git。把下面這些加進專案的 .gitignore。

口訣：先建 .gitignore，再 commit。不確定的檔案，先不要 commit。

驗證 .gitignore 是否生效

git status 不應該出現 .gguf、.env 等檔案。git diff --cached 確認暫存區裡沒有不該提交的東西。git check-ignore 有輸出就代表該檔案確實被忽略了。

Ollama 安全設定

Ollama 預設只綁定 127.0.0.1，意思是只有本機連得到它。不要把它改成 0.0.0.0，那會讓同一個網路上的任何人都能存取你的模型。保持 Ollama 更新到最新版，不要把 port 11434 暴露到不信任的網路上。
