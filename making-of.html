01 · Why · 為何是一頁式

為何要做一頁式指南

「你定義想要什麼，AI 把它變成能上線的東西。」 — 製作幕後頁留下的一句話

數字是 103 個 commits 與 9 份獨立指南。每一份都是可直接開啟的超文件標示語言（HyperText Markup Language，簡稱 HTML）檔案。它們都經歷過規劃與實作、驗證與修正，才推上 GitHub Pages（GitHub 提供的靜態網頁託管服務）。好奇的是，這樣的產量究竟是 AI 自動生成，還是把 AI 放進一個可驗證的生產系統所致。

同樣的困境很常見，熟悉台股的社會人士第一次接觸美股時，會被交易制度、稅務扣繳與券商流程同時淹沒。而傳統投影片只能線性播放。它無法讓讀者自行展開問答、切換漲跌顏色或列印成冊。需要的是一種載體，它在手機與桌機都能閱讀。它能把複雜制度收進可展開的區塊，並直接匯出為可攜式文件格式（Portable Document Format，簡稱 PDF）方便留存。

答案是一頁式互動網頁：把單一主題的全部知識收斂在同一個網址，讀者用捲動就能走完學習路徑，製作者則用同一個檔案完成維護。

為了讓這種載體可以量產，製作端引入驅動視覺設計的第三方工具 impeccable。它負責配色與字級、版面節奏等視覺細節，不必每次從空白畫布重新摸索美感。

02 · Plan · 計畫模式

模板不會替你想內容

最常被問的問題是，AI 是否只要一句話就能交出成品。回答非常明確，「計畫模式」才是整條產線真正的起點。做法是先把草稿丟給它，並說清楚讀者是誰，例如熟悉台股且第一次接觸美股的社會人士。因為對象決定了用字深淺與內容取捨，也決定了後續查證的嚴謹程度。

計畫模式要求 AI 先探索現況，把要做什麼與怎麼做寫成一份計畫，並在關鍵分岔點反問。

這次的分岔提問由誰決定
要投影片還是互動網頁？人
投資組合要不要寫具體標的？人
要不要順便啟用線上展示？人

看過計畫文件後逐項確認或修改，中途追加的要求例如第三方工具要附出處連結也在這個關卡補上，確認後 AI 才開始實作。

描述意圖，不是下指令。

這句心法貫穿了全部 9 份指南的製作過程。想要什麼、給誰看與底線在哪由人定義，把它變成可執行的計畫與程式由 AI 執行。這個環節省下來的時間，會在後面以十倍的規模回報。

計畫這一關的利息
因為計畫這一關沒有想清楚，後面每一次修正都是在為最初的模糊付出利息。AI 給答案不負責，負責的永遠是按下確認的我們。
03 · Tools · 工具揭露

工具誠實揭露才可信任

第二個堅持是誠實列出每一次調用的技能與外掛，並標示官方或第三方。所有第三方工具都附上出處連結，讀者可以自己找到並安裝。

為什麼工具清單要寫這麼細
可量產的關鍵，在於清楚知道每一個環節由誰負責。當讀者知道顏色由 impeccable 驅動、查證由搜尋完成、轉檔由 Chrome 與 PyMuPDF 把關，信任就有具體的落點。
04 · Verify · 修正循環

顏色壞掉才學會驗證

第三個要談的是修正循環，公式非常簡單：你描述需求後由 AI 實作，再用工具實際打開來看。確認的是真的修好，而不是看起來像修好。第一版不會完美，重點是建立可驗證的循環。

修正循環：你描述需求 → AI 實作 → 截圖／驗證 → 抓問題 → 修正

案例 1　抓到一個真實的 bug：顏色不會切換

綠漲紅跌與紅漲綠跌的切換鈕點了沒反應。AI 用預覽面板讀取網頁的實際計算樣式後，發現少寫了一段層疊樣式表（Cascading Style Sheets，簡稱 CSS）變數覆寫規則。它補上針對美國市場與台灣市場的兩行覆寫後，綠與紅正確互換了。點下面切換看差在哪：

:root{
  --rise: var(--up);   /* 綠 */
  --fall: var(--down); /* 紅 */
}
/* 切換到台股時，沒有任何規則改寫 --rise/--fall */
/* → 顏色永遠不變，按鈕像壞掉 */
✕ 缺少依市場切換的覆寫，顏色不會翻轉
:root{ --rise: var(--up); --fall: var(--down); }
#colorDemo[data-market="us"]{ --rise:var(--up);   --fall:var(--down); }
#colorDemo[data-market="tw"]{ --rise:var(--down); --fall:var(--up);   }
/* 切到台股 → 漲變紅、跌變綠，正確互換 */
✓ 補上兩行覆寫，切換立即生效

案例 2　一句話就能調整的內容

「下方給講者的備忘可以去除」，AI 直接刪掉該區塊，並重新載入預覽確認頁尾沒有留下空白。簡短而明確的指令在這裡最有效。

案例 3　更複雜的是整份匯出成 PDF

網頁轉 PDF 常見三個地雷：深色背景變白、互動問答收合後看不到答案、靠捲動才出現的圖表沒被畫出來。做法是加上列印樣式，強制印出背景並自動展開所有問答與補滿圖表，再用 PyMuPDF 逐頁檢查 13 頁是否都正確。

溝通三個訣竅
① 具體描述勝過模糊感受：說「頁尾備忘移除」比「再簡化一點」好下手。② 要求截圖或實測勝過想像：請 AI 實際打開來看。③ 分批一次改一處：讓每次變更都容易確認與回退。
05 · Ship · 推送與展示

推上線才是真的做完

檔案做好不等於別人打得開，只有推上 main 分支並啟用 Pages，任何人才能用網址直接開啟而不必下載檔案。

三步推上線

  1. 複製到本機——先把倉庫複製到本機。
  2. 推送變更——把檔案加入暫存、留下 commit 訊息並推送到遠端。本次依需求直接推上 main 分支，全程用 Git 完成版本紀錄。
  3. 啟用 Pages——用命令列工具一行完成，指定來源分支為 main 且路徑為根目錄；也可在倉庫網頁的設定頁點選分支後儲存。

啟用後的網址格式為 https://vik1n9.github.io/One-Page-Beginners-Guide/making-of.html。若還沒開啟 Pages，也可用 htmlpreview 直接預覽倉庫裡的 HTML 檔案，在它後面接上檔案的 GitHub 連結即可作為備援。

回頭看這 103 個 commits：它們是把從 0 到 1 的創意走進從 1 到 100 的量產時留下的腳印。

世界是可調參的系統，熱與碳與知識落差皆然，沒有必須忍受的權衡，只有還沒找到的參數。找到的參數就是先寫計畫、誠實揭露工具、用「驗證」代替想像，最後把成果推到人人可及的網址。
